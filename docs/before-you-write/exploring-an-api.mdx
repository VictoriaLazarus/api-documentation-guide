# Exploring an API

## Learning objectives

By the end of this chapter, you'll be able to:

- Explain why it's important to explore an API before documenting it.
- Identify the key information to gather before writing documentation.
- Navigate API documentation to understand available resources.
- Build a checklist for exploring a new API.

## Why explore an API first?

One of the many good advice you'll get as a technical writer is to take notes as you learn about a concept, instead of waiting till you learn everything about it before you start writing. But with API documentation, the reverse is best. It is very important that you explore the API first before you write. Find out how each endpoints in the API works before documenting. 

The reason is simple. Understanding the API helps you identify its capabilities, recognize how different endpoints relate to one another, and write documentation that is accurate and complete.

Exploring an API also helps you ask better questions when information is missing or unclear.

## Where to start

When you're introduced to a new API, begin by looking for its existing documentation.

API documentation often includes information such as:

- The purpose of the API
- Available resources
- Authentication requirements
- Base URL
- Available endpoints
- Request and response examples
- Error messages
- Rate limits

If documentation isn't available or is incomplete, work directly with developers and test the API yourself to understand how it behaves.

### Understand the API's purpose

Before looking at individual endpoints, understand what problem the API solves.

Ask questions such as:

- What does this API do?
- Who is expected to use it?
- What resources does it expose?
- What tasks can developers perform with it?

Understanding the API's purpose provides context for the rest of your documentation.

### Identify the available resources

Most APIs organize information into resources.

For example, a movie API might expose resources such as:

- Movies
- TV shows
- People
- Reviews
- Search

Each resource typically contains one or more endpoints that allow developers to retrieve or modify information.

Understanding how resources are organized makes it easier to structure your documentation.

### Examine the endpoints

Review the endpoints provided by the API.

For each endpoint, identify:

- The HTTP method
- The endpoint URL
- Required path parameters
- Optional query parameters
- Authentication requirements
- Request body, if applicable
- Response body
- Possible error responses

This information forms the foundation of your endpoint documentation.

### Review examples

Examples are one of the most valuable parts of API documentation.

As you explore an API, pay attention to:

- Sample requests
- Sample responses
- Authentication examples
- Error examples

These examples help you understand how the API behaves and provide useful references when writing your own documentation.

### Create an exploration checklist

As you dive into the API documentation, make sure you can answer the following questions:

- What problem does the API solve?
- Who is the intended audience?
- How is authentication handled?
- What resources are available?
- Which endpoints belong to each resource?
- What parameters does each endpoint accept?
- What responses and error messages can be returned?
- Are there any usage limits or special requirements?

If you can't answer these questions, continue exploring the API before documenting.

## Why this matters

Exploring an API isn't just about understanding the technology; it's about gathering the information needed to write accurate documentation.

The more familiar you are with the API before you begin writing, the easier it becomes to explain its behavior, identify missing information, and create documentation that developers can trust.

## Key takeaways

After completing this chapter, you should understand that why it is important to:

- Explore an API before writing its documentation.
- Gather key information about resources, endpoints, authentication, and responses.
- Review examples to understand how the API behaves.
- Use a checklist to ensure you have enough information before you start documenting.
