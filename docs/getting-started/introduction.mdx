# Introduction

API documentation can seem intimidating at first. I have been there and know how confusing unfamiliar terms like endpoints, HTTP methods, authentication, JSON, and status codes, can be. You may even begin to wonder if you need to become a software developer before you can document an API.

The good news is you don't.

This guide is designed to help you build a solid foundation in API documentation one concept at a time. It explains the basics, explores how APIs work, breaks down how to test endpoints, and gradually moves into writing clear, accurate, and useful API documentation. At the end, you'll have the knowledge and confidence to document your first API while also gaining hands-on experience with a modern docs-as-code workflow using Docusaurus.

## Why this guide exists

Many resources explain APIs from a developer's perspective, which made it difficult for one who has never written a line of code before to learn.

This guide bridges that gap.

It combines foundational API concepts with practical documentation techniques, helping you understand not only *what* to document but also *how* to communicate technical information clearly.

## Who this guide is for

This guide is designed for:

- Aspiring technical writers
- Junior technical writers
- Documentation engineers who are new to API documentation
- Developers who want to improve their documentation skills
- Anyone curious about how API documentation is created

No prior API documentation writing experience is required.

However, basic computer skills and a willingness to learn will help you get the most from this guide.

## What you'll learn

Throughout this guide, you'll learn how to:

- Describe what APIs are and how they work.
- Explain common API concepts in simple terms.
- Test API endpoints using Postman.
- Read and understand JSON responses.
- Document endpoints, parameters, authentication, requests, responses, and error messages.
- Apply documentation best practices.
- Use Markdown to write documentation.
- Understand the basics of Git and GitHub in a docs-as-code workflow.
- Build and publish documentation using Docusaurus.

## How this guide is organized

The guide is divided into six parts:

- **Part I: Getting started** introduces the prerequisites and tools you'll need.
- **Part II: Understanding APIs** explains the core concepts behind APIs.
- **Part III: Before you write** focuses on preparing to document an API.
- **Part IV: Writing API documentation** teaches you how to document endpoints effectively.
- **Part V: Documentation as code** introduces the tools and workflows commonly used by documentation teams.
- **Part VI: Final project** brings everything together as you document your first API.

Each chapter builds on the previous one, so it's recommended to work through the guide in order.

:::note

All the examples used in this guide are from the **[TMBD API](https://developer.themoviedb.org/docs/getting-started)**. 

:::

## How to use this guide

This guide includes explanations, practical examples, and hands-on exercises.

Whenever possible, follow along by testing APIs, experimenting with examples, and building your own documentation as you progress.

:::tip

Learning by doing is one of the most effective ways to develop API documentation skills.

:::
